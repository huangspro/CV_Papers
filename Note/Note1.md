# 关于VPR的笔记
VPR和text-VPR是**图片与图片**匹配，**图片与文本**匹配的子任务，或者说特例。其本质是将来自用户的**图片或文本提示词**进行处理，然后在已有数据库中寻找匹配提示词的条目。
目前的方法主要集中于
1. 将不同视角的图片和文本同统一**映射**到相同可比较的空间，然后在数据库中进行搜索
2. 与用户进行对话，每轮对话都基于之前对话的搜索结果进行文本提问，用户回答后进行下一轮检索提问，知道确信已经搜索到可靠结果

# 思考1
  - 这时，一个重要的问题自然是：**是什么使得VPR成为一个特殊的任务以至于普通的图片匹配和文本-图片匹配方法不能完全适用？**
  - 分析这个问题，即分析**VPR过程与普适匹配过程的不同**。基本思路自然是先观察数据流动的过程：
  - **数据集-输入-特征提取-压缩聚合-模态融合-数据库匹配-输出匹配结果**

## 数据集
  - vpr数据集包含信息为（视角图片-文本描述-地理位置），与普通文本-图片数据集不同的是：**不同视角的图片和描述可能代表同一个地点**。这样的话，vpr不仅要模拟图片与文本的匹配，还需要适应图片-文本对到地理位置空间的映射。这是一个核心的差异！
  - 这时，一个重要的想法是：**（摄像机，文本描述器）成为一个映射f：Location -> （image, text），我们需要的是f⁻¹ !**

## 特征提取
  - 差异是显然的。普通匹配任务需要关注图片中几乎所有事物，因为来自于文本的描述是多样的。例如，文本可能涉及颜色、纹理等等低级特征，也可能涉及物品、过程甚至文字等等高级语义。然而，VPR需要的是它们的子集，因为其文本指向性非常强。所以说：**文本提示是这类任务的关键控制因素！**
  - 或者，换句话讲，**text-VPR是一类由特殊指向的文本提示词引发的专用匹配任务！**。
  - 回到正题，VPR的特征提取聚焦于那些能够满足文本指向的特征：建筑、路面、标识、地形等等。
  - 这里有一个问题已经展现出来：不同的地点可能有相似的建筑。这时常见的，它们的区分极大依赖于建筑的排列，建筑周围的细微标志，建筑上挂着的物件等等。那么问题很明显
1. 模型无法区分这些细微而且高级的特征，因为它们需要很强的注意力。
2. 对这些特征的文本描述可能没有涉及到这些细致的区分项，因此，**DialogueVPR项目是有前瞻性的！**​

## 聚合
  - 不同模态的embedding vectors的聚合模式有多种，通常使用对比学习进行匹配。
  - 重要的是，聚合的过程中，可以根据图片特征删除文本中一些没有用的信息，即校准。
**这是很强的任务指向性！**
